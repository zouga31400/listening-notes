# Rules for this repository

When a message starts with "Playlist" (or "Playlists"), "Liste musique", "Liste Qobuz" or "Music list" (with or without a colon), the rest of the message is a playlist request, as short as "Playlist film Titanic" or "Playlist rock 90s, 15 titres". A name placed just before that word is the request's author: "Céline playlist film Titanic" is the request "film Titanic" by the author Céline. For it, produce a list of tracks that fits the request (30 tracks unless I say otherwise), in original studio versions, with exact artist and track names, and no duplicates. Write it in the expected format to lists/<short-name-without-accents>.txt, with a clear playlist name on the first line. Commit and push. Do not modify any other file. To fix an error reported in a log, modify lists_sync.py or the workflow only.

When the request is the music of a film (or a series), e.g. "film Titanic", list only the songs and existing tracks heard in it (licensed songs, original songs written for it, and existing instrumental tracks such as "Misirlou" in Pulp Fiction). Leave out the score composed for the film (orchestral themes and cues). If the film has few such tracks, give a shorter list with only those and say why it is short, instead of filling it with the score. Playlists get the description "Created by <author>": the default author is the `PLAYLIST_AUTHOR` GitHub secret (never write that name in this public repository); when my request names another author (e.g. "Céline playlist film Titanic", "Playlist rock 90s par Marie", "auteur Marie"), write it on an "Author: <name>" line right after the playlist name in a `lists/` file, or in the "Author" property of the Notion page. Name the film for the soundtrack check: a "Film: <title> (<year>)" line right after the playlist name in a `lists/` file, or the "Film" property of the Notion page. When the music service already has a soundtrack album with every song of the list, and those songs are at least half of the album, no playlist is created: the Notion page gets the status "Album" with the album link, and the notification opens the album. Otherwise the playlist is created as usual, with the album link added when the album holds at least half of the songs.

## Expected format

```
Playlist name
Artist - Title
Artist - Title
```

Pushing the file triggers `.github/workflows/lists-sync.yml`, which runs `lists_sync.py` and creates the private playlist on the music service. Do not modify `radio_listen.py` or `.github/workflows/radio.yml`.

The list is the reference for playlists created by this tool (description "Created by <author>", or the older "Created by lists_sync.py"): each run adds what is missing and removes tracks that are no longer chosen (wrong version, line removed) and duplicates. A playlist with the same name not created by the tool is only completed, never trimmed.

## Notion variant

`notion_lists.py` (workflow `.github/workflows/notion-lists.yml` on `main`, started every 2 min by an external call to the workflow_dispatch API, with a GitHub schedule as backup; runs with nothing to do delete themselves from the history on the next run) reads the "Playlist lists" Notion database, whose ID is the `notion_lists_db` key in `config.txt`. One page per playlist: title = playlist name, content = one "Artist - Title" line per track, "Status" property set to "To create". The script creates or syncs the playlist, replaces the "Sync report" at the bottom of the page (one line per track with the version and album picked, tracks not found, tracks removed) and sets the status to "Created" or "Error" (optional properties: "Added", "Not found", "Link"). Uses the `NOTION_TOKEN` secret, shared with the radio. At the end of each playlist (Notion page or `lists/` file), a push notification is sent through ntfy on the `NTFY_LISTS_TOPIC` secret, separate from the radio's `NTFY_TOPIC` (nothing is sent if it is not set).

When the Notion connector is available:
- These playlist requests can also go to Notion: create a page in "Playlist lists" (title = playlist name; content = one "Artist - Title" paragraph per track; Status = "To create"; for a film or series, Film = its title and year; Author = the author only when my request names one). Then, if GitHub tools are available, run the `notion-lists.yml` workflow on `main` right away instead of waiting for the schedule.
- "Check the playlist <name>" (or "Vérifie la playlist <nom>"): read the page's "Sync report". For each track that is not found or not the original studio version, correct or replace its line in the page content above the report (never edit the report itself), set Status back to "To create", and run the workflow as above. Summarize what was changed.

A playlist whose tracks have no album art gets a cover and icon chosen by `playlist_cover.py`, in this order: the film or series poster (Film property, from Wikipedia), the photo of the artist who makes up at least half of the list (from the music service, else Wikipedia), a theme cover for the genre named in the title (Soul, Rock, Jazz...), then for the decade (années 90, 1993-1996), then a neutral one. Theme covers are the PNG files of `covers/`, made by `tools/make_covers.py` and served from this public repository; add a theme there and in `GENRES` or `DECADES`. `notion_lists.py --backfill-covers` applies the same rule to older pages.

The Scriptable iOS app `scriptable/playlist-lists.js` ("Playlist Lists", same look as `scriptable/radio-soirees.js`) shows the "Playlist lists" database read-only: library with search, a "to follow" tab (waiting, in error, tracks not found), films, stats, and a home-screen widget. Its Notion key (read-only connection) is asked once and kept in the iOS keychain, never written in the repository. When the Notion properties used by the notion_lists.py report change, keep the app in step.

## Always-on listening outside the show

`radio_offshow.py` runs all the time on a small Oracle Cloud server (a systemd service; install and daily life in `deploy/oracle/README.md`, settings in `/etc/listening-notes/radio.env` on the server, never in the repository). Outside the show (daytime, weekends, the music before the detected start and after the detected end) it listens non-stop and fills its own playlists and the "Radio - Hors émission" Notion database (`offshow_*` keys in `config.txt`; no daily playlist; no notifications except errors). The show itself keeps `radio_listen.py`'s behavior: with `offshow_show_here = no` it stays on GitHub (`radio.yml`) and the server pauses from `listen_start` on weekdays until the "show ended" ntfy signal; with `yes` the server runs the show with `radio_listen.main(offshow=...)`, and the cron-job.org call that starts `radio.yml` must be turned off. The server pulls `main` every morning at 05:10. Changes to `radio_listen.py` must keep the show unchanged (`main()` without `offshow` behaves as before).

## Playlists sorted by mood and period

`sort_playlist.py` (workflow `.github/workflows/sort-playlist.yml` on `main`, checked every hour by an external call to the workflow_dispatch API with an empty `playlists` input, with a GitHub schedule as backup; only the rows that are due are sorted, `*` as input sorts every ticked row) makes copies of a playlist by mood (Calme / Groove / Énergique) and period (60-80s / 90-2000s / 2010s+). Which playlists and when come from the "Playlists to sort" Notion database (`notion_sort_db` in `config.txt`), one row per playlist: Name = exact playlist name, Active (ticked = sorted), Frequency (Daily / Weekly / Monthly), Day (Monday…Sunday; monthly = the first such day of the month), Hour (0-23, Paris time); empty = every Friday at 19:00. Last sorted, Copies and Result are filled in by the script.

The rules come from two other Notion databases in the "Musique" page (`notion_sort_settings_db`, `notion_genre_db` in `config.txt`; the `config.txt` values are the defaults): "Réglages du tri" (Calm up to, Energetic from, Copy name) and "Règles de genre" (one row per genre of the album on the service; "Playlist" = the tracks of that genre go only to that playlist, with no copy by mood and period and no audio analysis; "Energy points" = added to the measured energy before the mood is chosen; matching rows add up, and a word is enough: "Rock" matches "Pop/Rock"). Genres met and missing from the table are added to it after a sort (0 points, no playlist). A short notice is at the top of the "Musique" page.

When the Notion connector is available, requests such as "trie aussi ma playlist <nom>", "trie <nom> tous les jours à 8 h", "arrête de trier <nom>", "trie <nom> maintenant" or "où en est le tri de <nom> ?" are handled in that database, following the Notion skill "Trier une playlist par ambiance et période (ajouter, planifier, lancer)" in the "Musique" page: update the existing row rather than adding a duplicate, untick Active to stop (delete a row only when asked), clear Last sorted to sort at the next hourly check. For "now", if GitHub tools are available, also run `sort-playlist.yml` on `main` with the `playlists` input set to the playlist name. Requests such as "mets la musique classique à part" or "le métal +20 points" are a row in "Règles de genre" (update the genre's row if it exists). Do not change the code for these requests.
